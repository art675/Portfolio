Project 08 · Section 1

System Overview / Airframe / Hardware

PROJECT OVERVIEW

Project Phoenix was developed as a small UAV platform for externally localized, semi-autonomous search, pickup, and delivery demonstrations.

The team integrated a custom 3D-printed PLA airframe with four brushless motors, large propellers, LiPo power, Cube Orange flight control, radio telemetry, external Kinect sensing, and a suspended electromagnetic end effector.

The design evolved around real packaging and flight constraints.

Propeller diameter and motor selection increased, the frame was redesigned for additive manufacturing, and the payload mount was incorporated directly into the final structure.

CAD, fabrication, electrical integration, Python communication, flight controller configuration, camera-based localization, transformation analysis, and flight testing were shared across the team.

Project 08 · Section 2

Perception / Communication / Flight Testing

EXTERNAL LOCALIZATION FOR CLOSED-LOOP FLIGHT

Kinect depth sensing, Python vision processing, MAVLink communication, and flight-test validation

Kinect-assisted hover and localization test setup

Color segmentation with depth and camera-frame XYZ measurement

RGB-D LOCALIZATION PIPELINE

The Xbox 360 Kinect served as an external observer.

OpenCV isolated a colored tracking target and calculated its centroid, while the depth stream provided distance.

The pixel and depth measurements were converted into real-time Cartesian coordinates in the Kinect frame.

OpenNI handled depth-camera access, NumPy supported matrix operations, and Python provided the software layer used to transform measurements, inspect data, and communicate with the aircraft.

FLIGHT COMMUNICATION AND VALIDATION

The Cube Orange handled onboard state estimation, stabilization, and low-level control.

Mission Planner and ArduPilot were used for configuration, while MAVLink supported command transmission, telemetry, EKF-origin setup, and live troubleshooting.

The team demonstrated feedback-assisted flight using external position measurements.

Tests also revealed drift, indoor turbulence, and lighting sensitivity.

The full pickup-and-delivery mission logic was developed, but the complete end-to-end sequence was not integrated within the project timeline.

Project 08 · Section 3

Frame Transformations / Robotics Analysis

FROM CAMERA MEASUREMENTS TO TOOL-FRAME GUIDANCE

Homogeneous transformations connecting the universal, camera, drone, tool, and package reference frames

Frame relationships used to map Kinect measurements into the drone and end-effector coordinate systems

WHY THE TRANSFORMS MATTER

The Kinect reports target position in the camera frame, while the flight controller operates relative to the vehicle frame and the suspended electromagnet occupies a separate tool frame.

Raw camera coordinates therefore cannot be used directly for pickup guidance.

The analysis defined five useful frames: universal F_u, camera F_c, drone F_d, tool F_t, and package F_p.

Chaining homogeneous transformations allows the package pose measured by the camera to be expressed relative to the electromagnet.

HOMOGENEOUS TRANSFORMATION ANALYSIS

Known: ^u\!T_c, ^c\!T_p, ^c\!T_d, ^d\!T_t

For the experimental setup, the Kinect axes were treated as parallel to the universal frame.

The camera-to-universal relationship therefore contains only the measured translations x and z.

^t\!T_p = ^t\!T_d\, ^d\!T_c\, ^c\!T_p

^t\!T_p = (^d\!T_t)^-1 (^c\!T_d)^-1 ^c\!T_p

The two inverse transforms reverse the known drone-to-tool and camera-to-drone relationships.

Multiplying by the measured camera-to-package transform returns the package pose directly in the tool frame for final approach and alignment.
