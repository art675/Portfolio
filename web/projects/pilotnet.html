03 AUTONOMY / PROJECT 15

PILOTNET END-TO-END STEERING

Engineering portfolio case study

Project 15 · Section 1

Project Objective + Raw Data Problem

The final autonomy project moved from explicit lane-state logic to end-to-end learning.

A PilotNet-style convolutional neural network was trained to predict a continuous steering angle directly from a camera image.

Unlike classification, the output is a real-valued command, so the distribution of steering examples strongly affects what behavior the network learns.

WHY BALANCING COMES FIRST

The raw dataset is dominated by steering values near zero.

That is exactly what a vehicle produces when most recorded driving is straight or only mildly curved.

If the network is trained on this distribution unchanged, minimizing average error rewards the model for predicting near-straight steering too often.

Large steering angles are rarer, so their mistakes contribute less frequently to the training objective.

The first engineering task was therefore not model tuning.

It was reshaping the data so left, straight, and right steering examples were represented more deliberately.

Project 15 · Section 2

Mirror + Balance

The balancing workflow deliberately changed the steering-angle distribution before model training.

Horizontal mirroring first created opposite-sign steering examples, reducing left/right bias.

The steering range was then divided into eight bins and sampled to the same frequency so that hard-left, straight, and hard-right commands contributed more evenly to the regression problem.

WHY MIRRORING WAS NOT ENOUGH

Mirroring makes left and right steering more symmetric, but it still leaves the dominant central peak near zero.

A network trained on that distribution would continue seeing far more near-straight examples than large-angle turns.

BINNING MAKES THE TARGET DISTRIBUTION EXPLICIT

Eight steering ranges were populated evenly by sampling down to the least frequent bin.

This intentionally trades dataset size for a more uniform learning signal across the full steering-angle range.

NEXT: preserve this balanced target distribution when creating the training and validation subsets.

Project 15 · Section 3

Train / Validation Split

Balancing the full dataset was only useful if that structure survived the train/validation split.

Samples from each steering bin were therefore assigned to both subsets so the network learned from a broad steering range while the validation data independently tested how well that behavior generalized.

WHY BOTH SUBSETS MATTER

The training subset drives weight updates.

The validation subset is held out from those updates and acts as an independent signal for tuning, early stopping, and detecting poor generalization.

WHAT THIS ENABLES NEXT

With target imbalance controlled, changes in validation loss can be interpreted more meaningfully as effects of model training rather than simply the original steering-angle distribution.

Project 15 · Section 4

What Was Actually Tuned

Once the steering distribution was controlled, the remaining question was how to train the network stably.

The project varied learning rate, batch size, and effective training duration.

Validation loss was used as the main comparison signal because the goal was not simply to fit the training data, but to produce steering predictions that generalized to unseen frames.

BATCH SIZE

Changes how many samples contribute to one gradient update.

The report found the most useful range was approximately 64–128.

TRAINING DURATION

Early stopping limited wasted training, but the strongest runs still needed roughly 300 epochs to approach their best validation loss.

Project 15 · Section 5

Epoch Count Investigation

The first training question was whether additional epochs were still producing useful learning or merely pushing the model toward overfitting.

Two otherwise similar runs were compared at approximately 200 and 300 epochs.

Their validation loss histories reveal whether the model had actually reached a plateau.

MORE EPOCHS WERE STILL USEFUL

Both curves follow the same broad decay, but the longer run continues lowering validation loss after the shorter run ends.

In this case, additional training was still extracting useful structure rather than simply memorizing the data.

TRAINING LESSON

Early stopping should be treated as a safeguard, not as proof that fewer epochs are always better.

The validation history must first show that improvement has actually stalled.

Project 15 · Section 6

Learning Rate Investigation

The next experiment isolated learning rate, which controls the size of each weight update during gradient descent.

Two similar PilotNet runs were compared at 110^-4 and 210^-4.

The goal was to determine whether the slower setting was genuinely more stable or simply delaying useful convergence.

FASTER CONVERGENCE WITHOUT INSTABILITY

Within the tested range, the 2e-4 run reduced validation loss substantially faster.

The slower run remained at a higher loss for much of training instead of showing a clear stability advantage.

WHY THIS MATTERS

Learning rate changes how quickly the optimizer traverses the loss landscape.

Too large can overshoot useful minima, while too small can leave the model under-trained within the available epoch budget.

Project 15 · Section 7

Run-To-Run Variability

A final comparison used the same model structure and hyperparameter settings but different training runs.

The resulting validation curves diverged considerably.

This exposed an important machine-learning reality: random weight initialization and stochastic optimization can change how quickly an otherwise identical network reaches a useful solution.

TRAINING IS STOCHASTIC

One run begins improving much earlier than the other even though the architecture and nominal settings are the same.

A single training history therefore should not be treated as perfectly repeatable evidence.

ENGINEERING IMPLICATION

Repeated runs, fixed random seeds, and consistent evaluation data improve reproducibility.

Hyperparameter conclusions are stronger when they survive variation in initialization rather than depending on one favorable run.

Project 15 · Section 8

Model Output + Final Engineering Takeaways

The best model was evaluated by comparing its continuous steering output with the recorded ground-truth signal.

The network captures the broad sequence of left, straight, and right steering behavior, while the prediction remains smoother and more quantized than the recorded command in several regions.

That difference is exactly why validation loss alone is not enough: the final signal still has to be interpreted as a vehicle-control command.

ENGINEERING TAKEAWAYS

Data distribution is part of the controller.

A regression model only learns the steering behaviors represented in its training examples.

Validation history must be interpreted, not merely minimized.

A lower loss is meaningful only if the resulting steering signal is also physically useful.

Training is stochastic.

Repeated runs of the same architecture can converge differently because the weights begin from different random initializations.
