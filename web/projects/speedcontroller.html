Project 12 · Section 1

Problem Framing

03 AUTONOMY / / / PROJECT 12

This project extended the road-following vehicle from lane perception into scene-aware speed control.

Rather than commanding speed from a single visual feature, the controller interpreted traffic signs and signal states from a custom-trained YOLO detector, estimated when each object should affect the vehicle using its apparent image height, and reproduced the expected speed profile with deterministic control logic.

FROM IMAGE HEIGHT TO VEHICLE BEHAVIOR

As a traffic-control target approached the vehicle, its detected bounding-box height increased.

The controller used this image-height trend as a practical trigger for changing the commanded speed.

Detection class, object height, temporal hold, and release logic then determined when an action became active and when normal motion could resume.

DESIGN INTENT

The desired speed trace was treated as the reference behavior for the controller.

Rather than copying it directly, the project recreated that behavior with explicit logic built from detection class, apparent object height, temporal hold, sign priority, and release conditions.

Cp High Bay Gallery

GENERALIZING THE DETECTOR TO THE CP HIGH BAY

New lighting • • • New viewpoint • • • Same perception classes and control logic

The same detector was then exercised on the Cal Poly High Bay course.

The environment changed substantially, but the perception output retained the same interface: class label, confidence, bounding box, and lane evidence.

This was the more important test of whether the trained visual vocabulary transferred beyond a single recording.

WHAT CHANGED — AND WHAT DID NOT

Lighting, surrounding geometry, and viewpoint changed, but the detector still returned the same semantic classes needed by the speed controller.

That consistency allowed the downstream logic to remain independent of the specific test course.

Project 12 · Section 6

Perception To Speed Command

TURNING DETECTIONS INTO SPEED COMMANDS

Detection class • • • Height gating • • • Temporal hold • • • Priority logic

Once the detector had been validated, the final speed controller was kept deliberately interpretable.

Each recognized traffic-control class entered a small rule set that decided when the object was close enough to matter, how long its command should remain active, and which command should win when multiple detections appeared.

CONTROL BEHAVIOR

Height gating.

Bounding-box height acted as a proxy for distance, preventing far-away signs from changing the speed too early.

Temporal hold.

Stop, red-light, no-entry, and crosswalk commands remained active across multiple frames so a brief missed detection could not immediately cancel the maneuver.

Priority.

Safety-critical detections overrode normal speed-limit behavior, while a green-light detection could release a held red-light stop.

Return logic.

An end-speed-limit detection restored the nominal commanded speed after the constrained section.

Project 12 · Section 7

Odometry / Ackermann Validation

RECONCILING IMU ODOMETRY WITH ACKERMANN MOTION

IMU odometry • • • Ackermann kinematic reconstruction • • • Gain correction

WHAT THE COMPARISON REVEALED

The original kinematic reconstruction reproduced the overall course shape but did not match the odometry scale closely enough.

Applying a gain to the steering-model response brought the reconstructed path into substantially better agreement with the onboard motion estimate.

The exercise connected perception-driven commands to the physical vehicle model rather than ending the analysis at the camera output.

The recorded visualization shows the steering-angle and vehicle-motion signals used for the comparison and makes it possible to inspect how commanded steering evolved throughout the lap.
